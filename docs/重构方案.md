# ai-meta 重构方案（Comprehensive Chemometrics 驱动）

> 目标：把 `ai-meta-main` 从「脚本集」升级为「可复用、可组合、可验证的算法库」，
> 并把 Comprehensive Chemometrics 的方法体系逐条落进代码。
> 本文档是**设计方案**，不含产线代码改动；落地顺序见 §14。

---

## 0. 现状一句话总结

算法单点很强（CARS、自研 MCR、GLM 家族、LOGO/TSCV、GB3838 类别判定），
但**没有被组织成层**：预处理重复 5 份、模型库是硬编码 switch、阈值埋在 if-elif、
缺仪器迁移、缺指标、缺在线监控。

---

## 1. 现状诊断：8 个系统性缺口

| # | 问题 | 代码证据 |
|---|---|---|
| 1 | **同一条预处理链有 5 份实现** | `preprocessing.py` / `utils.py` / `river_inference.py` / `standard_solution_inference.py` / `local_regression_scripts/ai*/` 各抄一遍 SG→小波→SNV |
| 2 | **train / serve 已经不一致** | `river_inference.py` 文档自述：pca 变体的 SNV 是「全矩阵全局标准化」，与别处「逐条光谱 SNV」语义不同；且 **PCA 在推理时现拟合**，结果依赖同批次样本 |
| 3 | **没有仪器迁移，只能一机一模型** | `local_regression_scripts/ai14\|ai17\|ai18\|ai28/` 四套 `Regression.py`（11 KB × 4）高度重复 |
| 4 | **模型库是 `match-case` 硬编码** | `models.get_model()` 20+ 分支；加模型要同时改 `get_model`、`run.py` 的 `model_types`、`Train.py` |
| 5 | **指标阈值硬编码在 if-elif** | `preprocessing.get_configs()` 六个 `elif` 塞满 `ranges / cut_bound / review_upper / abs_error_bound / mape_bound` |
| 6 | **MCR 只有「半个」** | 自写 `WaterQualityMCR`（6 组分、非负、0.9/0.1 先验混合）；缺约束体系、缺初值估计、缺模糊性评估；`pyMCR` 已在 requirements 却未使用 |
| 7 | **评价逻辑有 bug + 僵尸代码** | `utils.evaluate()` 第 225 行 `target[i] > ranges[3]` 应为 `target[idx[i]]`；函数内 100+ 行注释掉的旧版本 |
| 8 | **统计与可视化没有独立层** | ACF/PACF 画在 `preprocessing.time_series_analysis()`；`utils.plot()` 470–633 行；无 LOD/LOQ、无控制图、无 MSPC |

## 2. 设计原则（四条）

| 原则 | 含义 |
|---|---|
| **SSOT** | 预处理算子、参数阈值、评价规则只定义一次，训练 / 推理 / 部署共用同一份代码 |
| **Registry 驱动** | 模型、预处理、变量选择、迁移、指标全部走注册表；新增能力 = 写一个类 + 一个装饰器 |
| **配置即实验** | YAML 描述「参数定义 + 预处理链 + 模型列表 + CV + 验收阈值」，不再靠改 Python |
| **Artifact 化** | 模型不是裸 `.pkl`，而是带 manifest 的 ModelCard（预处理链指纹、波长轴、数据版本、指标、仪器 ID），支持跨机迁移 |

## 4. core：一切可插拔的地基

### 4.1 `core/registry.py`

```python
class Registry:
    def __init__(self, name): self._d = {}
    def register(self, key, **meta):
        def deco(cls): self._d[key] = (cls, meta); return cls
        return deco
    def build(self, key, **kw): return self._d[key][0](**kw)
    def keys(self): return sorted(self._d)

MODELS    = Registry("models")      # @MODELS.register("pls", family="latent")
PREPROC   = Registry("preproc")     # @PREPROC.register("snv")
SELECTORS = Registry("selectors")
TRANSFER  = Registry("transfer")    # @TRANSFER.register("pds")
METRICS   = Registry("metrics")
```

新增一个模型只需：

```python
@MODELS.register("pls_daoyu", family="latent", needs=["X", "y"])
class PLS(PLSRegression): ...
```

`run.py` 的 `model_types` 列表与 `models.get_model()` 的 switch 随之消失。

### 4.2 `core/spectra.py`

```python
@dataclass
class SpectrumSet:
    X: np.ndarray            # (n_samples, n_wavelengths)
    wavelengths: np.ndarray  # 显式波长轴 —— 迁移/对齐的前提
    meta: pd.DataFrame       # instrument_id / timestamp / site / label columns
    def __post_init__(self): assert X.shape[1] == len(wavelengths)
```

> 现状 `preprocessing.get_configs()` 用魔法列号（`L+3`、`2*L+7`…）取列，
> `L` 还按 `daojin` 与否取 711/611。`SpectrumSet` 让波长轴与标签显式化，消除这类脆弱耦合。

### 4.3 `core/artifact.py` — ModelCard

```python
@dataclass
class ModelCard:
    model_key: str
    estimator: object
    preproc_chain: dict          # YAML 可复现的预处理链
    wavelengths: np.ndarray
    instrument_id: str           # 训练该模型所用仪器
    data_version: str            # 训练数据哈希
    fom: dict                    # SEN / LOD / LOQ / RMSECV / daily R²
    created_at: str
    def fingerprint(self): ...   # 部署端校验：链指纹 + 波长轴必须完全匹配
```

### 6.2 GLM 家族 + 过度离散自动诊断

现有 `preprocessing.get_configs()` 打印「方差/均值比 → 建议 gamma / poisson」，
但只是 print。应固化为 `models/glm.py` 的自动选择器：

```python
def pick_glm_family(y):
    r = np.var(y) / np.mean(y)
    return "gamma" if r > 1 else ("poisson" if abs(r - 1) < 0.1 else "negbinomial")
```

## 8. 仪器迁移工具箱（书 3.18）★ 最大增量

### 8.1 方法

```python
@TRANSFER.register("sbc")
class SBC:      # y' = a·y + b；最轻，标液即可标定

@TRANSFER.register("ds")
class DirectStandardization:
    """X_master ≈ X_slave @ F,  F = pinv(X_slave_std) @ X_master_std"""

@TRANSFER.register("pds")
class PiecewiseDirectStandardization:
    """逐波长窗口回归：x_master[:,j] = [1, X_slave[:, j-k:j+k+1]] @ b_j
       组装成带状 F；窗口宽度 k 由 CV 选。"""
    def fit(self, X_slave, X_master, window=5):
        n, p = X_slave.shape
        F = np.zeros((p + 1, p))                      # 含截距
        for j in range(p):
            lo, hi = max(0, j - window), min(p, j + window + 1)
            B = np.hstack([np.ones((n, 1)), X_slave[:, lo:hi]])
            F[:, j] = np.linalg.lstsq(B, X_master[:, j], rcond=None)[0]
        self.F = F
        return self
    def transform(self, X_slave):
        return np.hstack([np.ones((len(X_slave), 1)), X_slave]) @ self.F

@TRANSFER.register("glsw")   class GLSW: ...    # 不做标准化的传递（书 3.18.6）
@TRANSFER.register("coral")  class CORAL: ...

class TransferSampleSelector:   # Kennard-Stone / D-最优 / 基于 leverage
class InstrumentDiagnostics:    # 波长漂移估计、增益差、残差谱 → 判断该用 DS 还是 PDS
```

### 8.2 落地抓手：标液就是天然的标准化样本集

PDS / DS 需要「同一样本在两台仪器上的光谱对」，而项目**已经有** `standard_solution_inference.py`
的标液流程 —— 让每台工控机跑同一套标液，即得到 transfer 样本。

```yaml
# configs/instruments/ai17.yaml
master: ai14
transfer:
  method: pds
  window: 5
  standardization_samples: configs/standards/dayu_std_set_v3.yaml
  recalibration: monthly
  fallback: sbc          # 样本不足时降级
```

做到位后，`local_regression_scripts/ai14|ai17|ai18|ai28/` 四套重复脚本
收敛为 **一套通用 runtime + 每台机一个 transfer 参数文件**。

## 10. 计量验收（书 2.20 + GB3838）

现在 LOD 是硬编码常量（`lower_bound`），应改为**从数据算**：

```python
def multivariate_fom(model, X_cal, y_cal, X_blank):
    b = regression_vector(model)          # 回归向量
    SEN = 1.0 / np.linalg.norm(b)         # 灵敏度
    s_x = spectral_noise(X_blank)         # 空白光谱噪声
    gamma = SEN / s_x                     # 分析灵敏度
    s_0 = pred_std(model, X_blank)        # 空白预测标准差
    return dict(SEN=SEN, gamma=gamma,
                LOD=3.3 * s_0 / SEN, LOQ=10 * s_0 / SEN,
                selectivity=..., pred_interval=...)
```

- `water_standards.py` — GB3838 类别判定 + **跨类别误判矩阵**（现有 `evaluate` 的 ranges 逻辑）
- `acceptance.py` — 阈值驱动的规则引擎，输出合格证

> 注意：多元校正下的 LOD **不能**套用单变量 3σ，必须按 2.20 的多元定义。

## 14. 落地路线与优先级

| 阶段 | 内容 | 风险 | 收益 |
|---|---|---|---|
| **P0** | `preprocessing/` 抽取 + `configs/params.yaml` + train/serve parity 测试 | 低（回归测试护航） | 消灭 5 份重复与已知不一致 bug |
| **P0** | `core/registry.py` + `core/artifact.py`（ModelCard） | 低 | 后续所有「可插拔」的前提 |
| **P1** | `models/` 按 family 拆分 + registry 改造 | 中（`get_model` 保留兼容 shim） | 加模型不再动 3 个文件 |
| **P1** | `transfer/`（PDS/DS/SBC）+ 标液标准化样本集 | 中（需现场配合跑标液） | **四套工控机脚本收敛成一套** |
| **P2** | `metrics/`（多元 LOD/LOQ + 验收引擎）+ `stats/` | 低 | 计量验收从「拍常量」变「算出来」 |
| **P2** | `models/curve_resolution/` 补齐 + `selection/` 扩充 | 中 | 重叠峰 / 浊度干扰有本质解法 |
| **P3** | `viz/` + 自动报告；`monitoring/` 上线 | 低 | 交付物升级；在线异常可定位 |

### 我的推荐：先做这两件

1. **P0 预处理统一 + parity 测试** —— 当前唯一已造成实际 bug 的地方，重构风险最低，一周内可完成。
2. **P1 `transfer/`** —— 四台设备已在用四套几乎一样的脚本，而标液流程恰好提供了 PDS 必需的标准化样本，**投入产出比最高的一块新增**。完成后新站点上线从「重新训练 + 复制脚本」变成「跑一次标液 + 生成 transfer 参数」。

## 16. 验收标准：怎么算重构成功

| 检查项 | 判据 |
|---|---|
| 预处理单一实现 | 全仓库 `grep` 不到第二份 SG→小波→SNV 链 |
| train/serve 一致 | parity 测试通过；推理结果不再依赖同批次样本 |
| 加模型成本 | 新增一个模型 = 1 个文件 + 1 个装饰器，不动任何已有文件 |
| 阈值可配置 | 改量程/误差限只动 `params.yaml`，不动 Python |
| 跨机可用 | ai17 用 ai14 模型经 PDS 迁移后，daily R² 与本机模型差距 < 阈值 |
| 计量可辩护 | LOD/LOQ 由 `figures_of_merit.py` 算出，而非常量 |
| 回归护栏 | `test_deriv_matches_scipy` 及全部既有测试通过 |
